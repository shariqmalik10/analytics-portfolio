# Car-service analytics: Tableau case study

A one-page portfolio site showing the sales and subscription analytics I built in Tableau for a point-of-sale platform used by car service centres and garages in Saudi Arabia.

The site is live at https://shariqmalik10.github.io/analytics-portfolio/.

The original dashboards ran on live production data, so they can't be shared. The page shows the work in two ways:

- **Redrawn figures** of the sales dashboard, the Insights tab, the lifetime dashboard on Tableau Cloud and the orders-by-location flow in Tableau Prep. They keep each original's layout, palette and labels, and every number is a dummy value. In the sales dashboard, a cursor picks a city on the map and every card follows it.
- **Anonymised screenshots** of the original workbooks. Every figure is changed, client names are replaced with "Workshop NN", and the company name and logo are swapped for a placeholder brand, Motorly.

## How it's built

`index.html` is a static page with the text, the layout and the screenshot gallery. The figures are React components drawn with the stageshow kit. Vite builds them into one script and one stylesheet in `assets/figures/`, and the page loads those as plain files. The built files are committed, so GitHub Pages needs no build step.

| Path | Contents |
|---|---|
| `index.html` | The page |
| `assets/figures/` | The built figures. Generated by `npm run build`, and committed |
| `figures/scenes/` | One folder per figure, plus the shared Motorly styles in `shared/` |
| `figures/kit/` | The stageshow kit, MIT licensed (`figures/kit/LICENSE`) |
| `img/` | The anonymised screenshots |

## Run locally

Serve the folder, then open http://localhost:8000:

```bash
python3 -m http.server 8000
```

Don't open `index.html` straight from disk. Chrome refuses to run a module script on a `file://` page, so the figures stay blank.

## Edit the figures

You need Node.js 18, 20, or 22 and later. Install the build tools once:

```bash
cd figures
npm install
```

While you edit, keep a rebuild running. It rewrites `assets/figures/` on every save, so reload the page to see a change:

```bash
npm run watch
```

Before you commit, check the types and make a clean build:

```bash
npm run typecheck
npm run build
```

Then commit the rebuilt `assets/figures/` together with the source change.

Each figure is a folder in `figures/scenes/` with an `index.tsx` and a stylesheet. The dummy numbers are written in those files. The sales figure keeps its numbers in `scenes/sales/data.ts`. To add a figure, register it in `figures/main.tsx` and add a `<div data-figure="name">` to `index.html`.

Each figure has a wide design and a phone design. `index.html` reserves each figure's space with an `aspect-ratio` rule (`.fig--sales` and the others), and container queries switch it at the same width as the figure. If you change a figure's size or the width where it switches, change those rules to match, or the page jumps when the figure loads.

## Publish changes

GitHub Pages serves the site from the root of the `main` branch. Commit and push to `main`, and Pages redeploys within a minute or two:

```bash
git add .
git commit -m "Describe the change"
git push
```

Run `git status` before you commit, and check that nothing private is listed. The empty `.nojekyll` file tells GitHub Pages to serve the files as they are.

## Data privacy

- Every number in the figures is a dummy value. None of them are real.
- The screenshots in `img/` have already been anonymised.
- Never add the original screen recordings, raw screenshots or exports to this repo. `.gitignore` blocks common video formats as a safety net.
- GitHub Pages serves every file in the repo, so `.gitignore` also keeps out `CLAUDE.md`, `DESIGN.md` and `.claude/`. They hold private notes.
